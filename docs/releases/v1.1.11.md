# GoLiveBypass 1.1.11

**Hotfix de estabilidade** do ciclo 1.1.10: o bypass agora **sobrevive ao
reboot** de verdade (sem apertar o botão de novo), o Tor não derruba mais o
gateway nas rotações de circuito, e os instaladores de linha de comando
voltam a funcionar de ponta a ponta. Sem mudança de protocolo: a sinalização
continua em `*.discord.gg` por SOCKS5 e o WebRTC segue direto.

> **Como atualizar**
> - **GUI Windows**: auto-update via GitHub Releases (a 1.1.11-beta.3 é a
>   mesma build final). Se preferir manual, baixe
>   `GoLiveBypass-Portable-1.1.11.exe` e substitua.
> - **Plugin (Vencord/Equicord)**: auto-update pelo userplugin já publicado.
> - **Instaladores de terminal** (ps1/sh): baixe o instalador da release e
>   rode novamente — ele atualiza in-place.

## Destaques

### 🔁 O bypass volta sozinho no boot
Uma flag (`autoInject`) lembra que o bypass estava ativo. No boot, se a
injeção não estiver no disco, a GUI reativa sozinha — sem apertar o botão
verde de novo. E a injeção intacta não é mais revertida quando o PC desliga
sem quit limpo: o Discord abre **já injetado**. Desativar pelo botão segue
respeitado (o boot não re-injeta).

### 🐧 Windows — modo de rede que a GUI escolhe é o modo que roda
Trocar o modo no seletor agora reescreve a injeção na hora (vale no próximo
start do Discord) e o fallback das gratuitas enxerga o Tor da GUI na 9060 —
antes ele varria só as portas clássicas e o gateway saía direto com o Tor de
pé ([#121](https://github.com/bezumiya/GoLiveBypass/issues/121)).

### 🧅 Tor — rotação de circuito virou non-event
O Tor renova circuitos a cada ~10 min e o bypass derrubava a saída única
nesse intervalo (probe de 4s vs. construção de 5-30s), deixando o gateway
fora por minutos. Batimento agora é informativo no modo tor e o túnel do
gateway espera até 30s — a reconexão atravessa a construção do circuito
([#122](https://github.com/bezumiya/GoLiveBypass/issues/122)).

### 🪟 Autostart que funciona de verdade
- A Run key era gravada com o exe **extraído do %TEMP%** do portable —
  limpou o temp, o app não abria no boot com o checkbox marcado. Agora grava
  o exe original e se auto-cura a cada abertura.
- O Tor do logon não abre mais **janela de terminal** (wrapper invisível via
  wscript).

### 🖥️ Instaladores de linha de comando
- Injeção nova voltou a funcionar: o `--location` do Vencord/Equicord
  instala recebe a **raiz** (`...\Discord`), não o `app-1.0.x`.
- Seletor de Discords mostra os nomes de novo (checkboxes vazios corrigidos,
  no instalador e no standalone).
- Falha de injeção agora diz **qual** Discord falhou e com qual código de
  saída no relato automático
  ([#120](https://github.com/bezumiya/GoLiveBypass/issues/120)).

### 🩺 Diagnóstico para o suporte
Novo `diagnostico.ps1`: o usuário roda e manda o `.txt` do Desktop — Run key
(com detecção de caminho morto), tarefas, processos, portas, logs, eventos
de erro e estado de injeção. A proxy do usuário é ocultada automaticamente.
